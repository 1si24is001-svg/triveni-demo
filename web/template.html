    How TRIVENI decides

    Eight stages turn three noisy sources into one list of matches for every Source 1 business. Stages 1 to 4 shrink the search; stages 5 to 7 are the machine learning.

    1. Read the sourcesSource 1 is the reference list; Sources 2 and 3 are searched for matches.
    2. NormalizeMap Indic scripts to Latin, fold accents, merge dotted letters, expand abbreviations, extract postcodes, house numbers and landmarks with regular expressions, and build a phonetic key.
    3. Block with weighted keysRecords sharing a rare key (name sound, prefix, postcode, house number) become candidates, weighted by ln(1 + N / df).
    4. Re-rankCharacter-trigram cosine similarity keeps the 8 best candidates for each business.
    5. Stage-1 LightGBMGradient-boosted trees score each pair from Jaro-Winkler, Levenshtein, IDF overlap, postcode and house-number features.
    6. Stage-2 LightGBMA second model sees the neighbourhood: rank among candidates, competing claims on the same record, and triangle support across sources.
    7. Calibrate and decideIsotonic regression gives true probabilities; each business gets the match set with the highest expected F0.5.
    8. OutputOne row per Source 1 business with its matched records.

    The demo data is synthetic. It copies the format and noise of the Amazon ML Challenge data, including names written in Hindi, Kannada and Tamil script, so the full pipeline can run live in a browser.
